RED LITE · LOCAL INFERENCE ON A 24 GB MAC

Run an 80B model on a 24 GB Mac.

DwarfStar Red Lite is a narrow C, Objective-C and Metal engine for one model family: Qwen3-Next-80B-A3B and Qwen3-Coder-Next. It streams experts from the SSD, decodes speculatively without changing the answer, and serves an OpenAI-compatible API to your coding agent.

PRINCIPLE · SPARSE MODEL, SMALL MAC

An 80B model that touches 3% of itself per token.

A red dwarf is the smallest true star. Red Lite is the same idea as DwarfStar, made to fit the smallest Mac that can hold an 80B model.

01 · THE MODEL

80B parameters

Qwen3-Next has 48 layers, each with 512 experts. At 2 bits the whole file is 19.3 GB.

02 · THE TOKEN

3B in use

Each layer picks 10 of its 512 experts per token. Only about 1.4 GiB of weights is read every time.

03 · THE MAC

24 GB is enough

The dense weights stay in memory and the experts are a cache read from the SSD. With a raised GPU limit, every expert stays on the GPU.

DESIGN · WHAT IS DIFFERENT

Written for one model, checked against llama.cpp.

Its own kernels

Gated DeltaNet, attention and the 512-expert MoE in Metal, each checked against a CPU reference and llama.cpp before use. llama.cpp is a test oracle, never linked.

Experts from the SSD

A bounded cache with cache-aware routing, at most 0.2% perplexity cost. It is the default on 24 GiB Macs: nothing to configure.

A better 2-bit file

Red Lite's own quantization, F2, has the size of the usual IQ2_XXS and a 6% lower perplexity. It is on Hugging Face.

Exact speculation

MTP drafts a token and checks it in the same pass: up to 30% faster, and the answer never changes.

An API for agents

OpenAI chat completions with tool calling, rendered exactly as the model's own chat template, so agent turns keep the engine state.

Honest numbers

Every result names the Mac it was measured on, and what did not work is written down too.

INSTALL · THREE STEPS

From zero to a local 80B chat.

Homebrew installs prebuilt binaries; the model downloads from Hugging Face.

# 1. install
$ brew tap alfofire2/redlite https://github.com/alfofire2/dwarfstar-red-lite
$ brew trust --tap alfofire2/redlite
$ brew install redlite
# 2. download the model (19.3 GB) and the MTP head (2.4 GB)
$ redlite download 24gb && redlite download mtp
# 3. check the Mac and chat
$ redlite doctor && redlite chat

From source: the README. On a 48 GiB Mac, redlite download 48gb fetches the higher-quality IQ3_XXS file.

INTEGRATION · CODING AGENTS

A local server for your coding agent.

redlite serve --native speaks the OpenAI chat API with tool calling. redlite setup-pi configures the pi coding agent in one command.

On harder tasks on a real repository, Qwen3-Coder-Next at 2 bits passed 70% against 83% for the full-precision model.

$ npm install -g @earendil-works/pi-coding-agent
$ redlite setup-pi --port 8080
$ redlite serve --native --context 32768 --port 8080
$ pi --provider redlite --model qwen3-next-80b-a3b-redlite

FAQ · COMMON QUESTIONS

Questions.

Can I run an 80B model on a 24 GB Mac?

Yes, Qwen3-Next-80B-A3B: a token uses about 3B of its 80B parameters. By default Red Lite keeps about 1.4 GiB of dense weights and a 4 GiB expert cache in memory and reads the rest from the SSD: 34 tok/s on an M4 Pro 24 GiB. With a raised GPU limit every expert stays on the GPU: 45 tok/s, 49–58 with MTP.

How is it different from DwarfStar?

DwarfStar (antirez/ds4) by Salvatore Sanfilippo is the original project. Red Lite applies its idea to another model, Qwen3-Next, and a smaller Mac. It shares no code with DwarfStar and is not affiliated with it; the name is a tribute.

How does it compare with llama.cpp, Ollama, LM Studio or MLX?

Against llama.cpp on the same files: 86.2 vs 72.5 tok/s on an M4 Max 48 GiB, 45–46 vs 36–38 on an M4 Pro 24 GiB. Ollama, LM Studio and MLX were not measured.

Which Mac do I need?

Apple Silicon with 24 GB of memory or more. Tested on an M4 Pro 24 GiB and an M4 Max 48 GiB. M1, M2 and M3 should work but have not been tested.

Does it work with Qwen3-Coder and coding agents?

Yes. Qwen3-Coder-Next runs the same way, and on harder agent tasks it passed 70% at 2 bits against 83% for the full-precision model.
