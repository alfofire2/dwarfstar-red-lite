DwarfStar Red Lite

Qwen3-Next 80B and Qwen3-Coder on a 24 GB Mac. A local LLM runtime in native Metal, written for this one model family, in the spirit of antirez's DwarfStar.

An 80B model that touches 3% of itself per token

Qwen3-Next-80B-A3B has 80 billion parameters, but each token uses only about 3 billion: every one of its 48 layers picks 10 of 512 experts. Red Lite keeps the dense weights in memory and treats the experts as a cache read from the SSD, so the model runs on a MacBook Pro with 24 GB of unified memory. With a raised GPU limit it keeps every expert on the GPU.

34 tok/son an M4 Pro 24 GiB, nothing to configure
45–58 tok/swith every expert on the GPU, MTP speculative decoding
19% fasterdecode than llama.cpp on the same file, M4 Max

Install

brew tap alfofire2/redlite https://github.com/alfofire2/dwarfstar-red-lite
brew trust --tap alfofire2/redlite
brew install redlite
redlite download 24gb && redlite download mtp
redlite chat

Or build from source: instructions in the README. Models are standard GGUF files on Hugging Face.

A local server for coding agents

redlite serve --native speaks the OpenAI chat API with tool calling, rendered exactly as the model's own chat template, so an agent's turns keep the engine state instead of re-reading the prompt.

npm install -g @earendil-works/pi-coding-agent
redlite setup-pi --port 8080
redlite serve --native --context 32768 --port 8080
pi --provider redlite --model qwen3-next-80b-a3b-redlite

What makes it different

  • Written for one model. The Gated DeltaNet, attention and 512-expert MoE kernels were each checked against a CPU reference and llama.cpp before use.
  • Expert streaming from the SSD, with a bounded cache and cache-aware routing (at most 0.2% perplexity cost).
  • A better 2-bit file. Red Lite's F2 has the size of the usual IQ2_XXS and a 6% lower perplexity.
  • MTP speculative decoding that never changes the answer.
  • Honest numbers. Every result names the Mac it was measured on, and what did not work is written down too.

FAQ

Can I run an 80B model on a 24 GB Mac?

Yes, Qwen3-Next-80B-A3B. A token uses about 3B of its 80B parameters. By default Red Lite keeps about 1.4 GiB of dense weights and a 4 GiB expert cache in memory and reads the rest from the SSD: 34 tok/s on an M4 Pro 24 GiB. With a raised GPU limit every expert stays on the GPU: 45 tok/s, 49–58 with MTP.

How is it different from DwarfStar?

DwarfStar (antirez/ds4) by Salvatore Sanfilippo runs DeepSeek V4 and GLM on large Macs. Red Lite applies the same idea to Qwen3-Next and a smaller Mac. It shares no code with DwarfStar and is named after it as a tribute: red dwarfs are the smallest true stars.

How does it compare with llama.cpp, Ollama, LM Studio or MLX?

Against llama.cpp on the same files: 86.2 vs 72.5 tok/s on an M4 Max 48 GiB, 45–46 vs 36–38 on an M4 Pro 24 GiB. Ollama, LM Studio and MLX were not measured.

Which Mac do I need?

Apple Silicon with 24 GB of memory or more. Tested on an M4 Pro 24 GiB and an M4 Max 48 GiB. M1, M2 and M3 should work but have not been tested. Reports are welcome.

Does it work with Qwen3-Coder and coding agents?

Yes. Qwen3-Coder-Next runs the same way, and on harder agent tasks it passed 70% at 2 bits against 83% for the full-precision model.
